# 個人網站開發方向

以下為未來方向建議，尚未決定實作。評估日期：2026-10-11。

## 現況與目標

目前網站具備雙語自我介紹、公開服務入口與 GitHub 連結，設計簡潔，適合快速查找服務。主要缺口是個人特色與作品深度：訪客能開啟服務，卻不容易了解站主的參與角色、成果與技術思考。

建議發展成精簡的個人作品集，保留服務入口，將詳細案例與文章放在獨立頁面。初期以同儕與潛在合作對象為主要讀者；若改以求職或研究交流為目標，再調整內容重心。

## 可新增的內容

| 方向       | 內容與價值                                                                                             | 維護需求                 |
| ---------- | ------------------------------------------------------------------------------------------------------ | ------------------------ |
| 精選作品   | 從兩個代表案例開始，說明問題、個人貢獻、做法與成果，搭配截圖及公開連結。清楚區分開發、協作與代管角色。 | 專案變動時更新           |
| 個人介紹   | 補充關注領域與歡迎的合作方式，視需要加入經歷、履歷或選定的聯絡方式。                                   | 定期檢視                 |
| 技術文章   | 分享公開專案的決策、開發經驗與學習筆記，讓訪客看見思考過程。                                           | 需持續投入寫作與雙語翻譯 |
| 近況與興趣 | 精選學習近況、閱讀筆記或工具使用心得，增加個人特色。                                                   | 有穩定更新習慣再加入     |
| 互動展示   | 展示與作品相關的遊戲機制、演算法視覺化或小工具。                                                       | 開發與維護成本較高       |
| 服務狀態   | 有使用者需求時，優先連到既有公開狀態頁。                                                               | 自建監測需持續維運       |

## 設計方向

| 選項                       | 特色與取捨                                                                     |
| -------------------------- | ------------------------------------------------------------------------------ |
| 編輯式作品集，建議優先採用 | 延續中性色與青綠色配色，強化自我介紹與精選作品預覽；改動適中，也容易擴充文章。 |
| 視覺作品展示               | 以大截圖與作品網格呈現成果；適合視覺完整的專案，但需要品質一致的素材。         |
| 開發者筆記                 | 以文章、作品摘要與技術示意圖為主；適合把持續寫作作為網站重心。                 |

首頁建議依序呈現「自我介紹 → 精選作品 → 公開服務 → 個人連結」，有文章後再加入近期筆記。保留容易閱讀的版面與明暗模式，讓作品閱讀入口和服務操作入口清楚區分。

## 開發優先順序

1. **P1：補強個人特色與作品。**確認目標讀者，完成兩個代表案例，改善自我介紹與服務入口，加入作品預覽及基本分享資訊。讓訪客能快速理解你做什麼、貢獻了什麼。
2. **P2：建立文章與背景內容。**第一批完整雙語文章準備好後，加入文章列表與 RSS；依讀者需求補上「關於我」或履歷。
3. **P3：依需求擴充。**再選擇互動展示、近況頁或服務狀態。文章累積後才考慮搜尋，避免一次加入太多需要長期維護的功能。

## 開發範圍

維持雙語內容與靜態網站架構，作品資料只使用可公開的內容。新增頁面與互動功能時，沿用 [AGENTS.md](../AGENTS.md) 的專案規範。

留言、帳號、聯絡表單後端、即時外部元件與流量分析，等有明確需求再評估。優先投入作品內容與閱讀體驗。
